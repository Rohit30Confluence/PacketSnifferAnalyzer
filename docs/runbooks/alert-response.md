# Runbook: Alert Response

**Version:** 1.0
**Audience:** Security analysts
**Last Updated:** 2026-07-29

## Overview

This runbook covers the response procedures for alerts generated by PacketSnifferAnalyzer's alert engine.

---

## Alert Severity Levels

| Severity | Description | Response Time |
|---|---|---|
| CRITICAL | Immediate threat; active attack likely | Immediate |
| HIGH | Significant anomaly; investigation required | Within 15 minutes |
| MEDIUM | Notable deviation; monitor closely | Within 1 hour |
| LOW | Informational; review at next opportunity | Next business day |

---

## Built-in Alert Rules

### SYN Flood Detection

**Trigger:** More than 1,000 SYN packets per second from a single source IP within a 10-second window.

**Response:**
1. Identify the source IP from the alert context
2. Check if the source is a known scanner or load balancer
3. If malicious: apply firewall rule to block the source
4. Export the relevant PCAP segment for evidence:
   ```bash
   psa export -s <session> -f pcap -o syn-flood-evidence.pcap \
     --filter "tcp.flags.syn == 1 and ip.src == <source-ip>"
   ```

### Port Scan Detection

**Trigger:** A single source IP connects to more than 100 distinct destination ports within 60 seconds.

**Response:**
1. Identify the scanning source IP
2. Determine if this is authorized scanning (e.g., vulnerability scanner)
3. If unauthorized: block the source and escalate
4. Document the scan scope from the flow table:
   ```bash
   psa flows --filter "ip.src == <source-ip>"
   ```

### High Bandwidth Alert

**Trigger:** Traffic exceeds the configured bandwidth threshold.

**Response:**
1. Identify the top talkers:
   ```bash
   psa top-talkers --n 10
   ```
2. Determine if the traffic is expected (backup, update, etc.)
3. If unexpected: investigate the source and destination

## Viewing Alert History

```bash
# View recent alerts
tail -50 ~/.packetanalyzer/logs/alerts.log | python -m json.tool

# Filter by severity
grep '"severity": "HIGH"' ~/.packetanalyzer/logs/alerts.log

# Filter by rule
grep '"rule_name": "SYN Flood Detection"' ~/.packetanalyzer/logs/alerts.log
```

## Configuring Alert Rules

Alert rules are defined in YAML format:

```yaml
# configs/alert_rules.yaml
rules:
  - rule_id: syn-flood-001
    name: SYN Flood Detection
    description: Detects SYN flood attacks
    condition: syn_flood
    threshold: 1000
    window_seconds: 10
    severity: HIGH
    actions:
      - CONSOLE
      - LOG
      - WEBHOOK
    webhook_url: https://hooks.example.com/alerts
    enabled: true
```

Load rules at startup:
```bash
psa capture start -i eth0 --alert-rules configs/alert_rules.yaml
```
